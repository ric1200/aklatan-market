1. WHAT YOU NEED
================================================================================

  * An e-mail address.
  * This package, extracted so you can see the files (config/, database/,
    includes/, assets/, admin/, the .php files in the root, etc.).
  * About 45 minutes and a bit of patience with the first upload.

You do NOT need: a credit card, a domain name, npm/Node, Composer, a VPS,
Docker, or any paid service. The shop uses only PHP and MySQL, which the free
plan already provides.

TIP: The whole package is small (about 2 MB, 143 files). The database import
file is about 58 KB, so phpMyAdmin will import it without any special tricks.

2. STEP 1 - CREATE A FREE ACCOUNT AND A FREE SUBDOMAIN
================================================================================

  1. Go to  https://dash.infinityfree.com/register  and sign up with your
     e-mail address. Confirm the e-mail if they ask you to.
  2. In the client area, choose to create a new hosting account.
  3. When asked for a domain, pick "free subdomain" and type the name you want,
     for example  aklatanmarket  with the extension  .rf.gd  - which gives you
     https://aklatanmarket.rf.gd  (extensions such as .rf.gd, .great-site.net
     and about 25 others are offered; if your first choice is taken, try
     another name or extension).
  4. Wait for the account to become active. InfinityFree has to register the
     subdomain, which usually takes a few minutes; the client area shows the
     status. You can continue with step 3 in the meantime if your database
     section is already available.
  5. Write down: your subdomain, and the hosting account password. The password
     for the database and FTP is the HOSTING ACCOUNT password, which is NOT the
     same as your client-area login password.


================================================================================
3. STEP 2 - CREATE THE MYSQL DATABASE
================================================================================

  1. In the client area open  Accounts , find your hosting account and press
     Manage , then press  Control Panel .
  2. In the control panel open  MySQL Databases .
  3. Type a short label for the database, for example   aklatan  , and press
     Create Database . Letters and numbers only.
  4. The database is created with a long technical name. InfinityFree will show
     something like:

        MySQL DB Name    : if0_38612345_aklatan
        MySQL User Name  : if0_38612345
        MySQL Host Name  : sql113.infinityfree.com     (example - copy YOURS)

     The exact host name differs from account to account. Copy the values that
     YOUR control panel shows; do not copy the examples above.
  5. Leave the page open, or copy the four values into a note:
     database name, user name, host name, and the account password.


================================================================================
4. STEP 3 - THE FOUR VALUES YOU NEED
================================================================================

  DB_HOST   The MySQL Host Name shown in MySQL Databases, e.g.
            sql113.infinityfree.com   <-- NEVER use "localhost" on free
            hosting; it will not connect.
  DB_NAME   The full database name, e.g. if0_38612345_aklatan
  DB_USER   The MySQL User Name, e.g. if0_38612345
  DB_PASS   Your hosting account password (use the Show link in the client area
            if you have forgotten it).

  Keep these four values handy for step 5.


================================================================================
5. STEP 4 - IMPORT THE SQL FILE WITH PHPMYADMIN
================================================================================

  This creates all 17 tables and fills the shop with a realistic starter
  catalogue (47 titles in 10 categories, a few sample customers, orders and
  reviews so the shop does not look empty on day one).

  1. Control Panel  ->  phpMyAdmin .
  2. In phpMyAdmin, click your new database in the left-hand list, then press
     Connect Now if you are asked.
  3. Click the  Import  tab at the top.
  4. Press  Choose File  and select  database/aklatan_market.sql  from this
     package (it is inside the  database  folder).
  5. Leave the other options as they are and press  Go  at the bottom.
  6. After a few seconds you should see a green success message. On the left you
     should now see tables such as users, products, orders, order_items,
     payments, reviews, store_settings and audit_logs.

  If the import seems to do nothing, scroll down: phpMyAdmin prints the result
  at the bottom of the page. A red error message usually means you forgot to
  select the database in step 2, or that you are importing into a different
  database than the one you configured later in config/config.php.


================================================================================
6. STEP 5 - EDIT THE ONE CONFIGURATION FILE
================================================================================

  The ONLY file you must edit is:   config/config.php

  It ships with empty database values, so the shop will show a friendly
  "finish the installation" page until you fill it in. That is normal.

  HOW TO EDIT IT
    * Download  config/config.php  from the package, open it in Notepad
      (Windows) or TextEdit/any plain-text editor, and change the five lines
      below. Then upload it back, overwriting the old file.
    * Many hosting File Managers also let you edit a file directly in the
      browser (right-click the file -> Edit). Either way works.
    * Keep the quotes and the semicolon. Never delete the <?php line at the top.

  WHAT TO CHANGE (near the top of the file)

      define('DB_HOST', 'sql113.infinityfree.com');   // your MySQL Host Name
      define('DB_NAME', 'if0_38612345_aklatan');      // your database name
      define('DB_USER', 'if0_38612345');              // your database user
      define('DB_PASS', 'your-hosting-account-password');
      define('DB_PORT', 3306);                        // leave as 3306

  THE SITE ADDRESS - leave this alone unless you need it

      define('SITE_BASE_URL', '');

  An empty value is correct for almost everybody: the shop works out its own
  address, whether you are at the root of your subdomain, in a sub-folder, or
  on a custom domain. Only fill it in if your links look wrong later, for
  example:

      define('SITE_BASE_URL', 'https://aklatanmarket.rf.gd');
      (no trailing slash, include https:// if your certificate is active)

  TWO MORE SWITCHES WORTH KNOWING

      define('APP_DEBUG', false);   // keep FALSE on the live shop. TRUE prints
                                    // technical details on screen - only for
                                    // short troubleshooting sessions.
      define('FORCE_HTTPS', false); // set to TRUE once your SSL padlock works
                                    // (see section 11).

  You can also change the store timezone (Asia/Manila is the default), the
  maximum uploaded image size (2 MB), and the failed-login limits
  (LOGIN_MAX_ATTEMPTS / LOGIN_LOCKOUT_MINUTES) in the same file.

  config/config.example.php is an identical template if you ever overwrite
  config.php by accident.

  WHAT NOT TO DO
    * Do not put your database password inside any other file.
    * Do not re-upload a config.php that still contains someone else's values.

7. STEP 6 - UPLOAD THE WEBSITE FILES
================================================================================

  Everything in this package goes INTO the  htdocs  folder of your hosting
  account. htdocs is the folder the internet can see.

  METHOD A - online File Manager (easiest)
    1. Control Panel  ->  File Manager  (sometimes called "Online File Manager").
    2. Open the  htdocs  folder. If you have several domains in one account,
       make sure you are in the htdocs folder of YOUR subdomain (on some
       accounts this is a folder named after the domain, e.g.
       aklatanmarket.rf.gd/htdocs).
    3. Upload the files. Most File Managers let you select many files, or a
       ZIP, and then Extract / Unzip.
         - If you upload a ZIP, extract it inside htdocs and delete the ZIP
           afterwards so it cannot be downloaded.
    4. Check that htdocs now directly contains index.php, products.php,
       cart.php, the config, includes, admin, assets and database folders.
       index.php must NOT be one level deeper (a very common mistake).

  METHOD B - FTP (faster for 143 small files)
    1. FTP host:      ftpupload.net
       Port:          21
       Username:      shown under FTP Details in the client area
       Password:      your hosting account password
    2. Use any FTP client (FileZilla is free). Connect, open htdocs on the
       right-hand side, and drag the CONTENTS of this package into it.
    3. Upload the folders  admin, assets, config, database, includes, account,
       storage, uploads  and the  .php files. Upload  .htaccess  too - you may
       need to tell your FTP client to show hidden files (it starts with a dot).

  FINAL LAYOUT CHECK (this is what it must look like)

      htdocs/
        index.php          <- the home page
        products.php   product.php   cart.php   checkout.php ...
        login.php   register.php   logout.php   wishlist.php   search.php
        403.php   404.php   500.php   setup_admin.php
        .htaccess          <- optional but recommended hardening
        account/    admin/    assets/    config/    database/    includes/
        storage/    uploads/

  Folder permissions: 755 for folders and 644 for files is correct on
  InfinityFree. You normally do not have to change anything: uploads/products
  and uploads/payments must be WRITABLE so product images and payment receipts
  can be saved. If image upload fails later, set those two folders to 755 (or
  775) in the File Manager and try again.

8. STEP 7 - CREATE THE FIRST ADMINISTRATOR
================================================================================

  You need an administrator account to manage the shop. There is deliberately
  NO default username or password in this package, so nobody can guess your way
  in.

  1. In your browser open:   https://your-subdomain/setup_admin.php
  2. Fill in your name, the e-mail address you want to sign in with, and a
     password of at least 10 characters. Do not use something like
     "password123"; the page refuses a few of the most obvious ones.
  3. Read the checkbox about the sample shop data:

        [ ] Delete the sample customers, orders and reviews from my shop

     * Leave it UNTICKED if you want the demo catalogue, sample customers and
       sample orders to stay while you explore. Recommended for your first run.
     * TICK it when you are ready to open for real business: it removes every
       account ending in @example.com together with their orders, order items,
       payments, reviews, wishlists, addresses and the sample enquiries. Your
       real products, categories and store settings are kept.
     * You can also do this later: sign in as admin, open any customer whose
       address ends in @example.com and delete it, or ask your hosting support
       to run:
           DELETE FROM users WHERE email LIKE '%@example.com';
  4. Press the create button. You are signed in immediately and taken to the
     admin dashboard.

  >>> STEP 7b - DELETE setup_admin.php FROM YOUR SERVER <<<

     Open the File Manager (or FTP), go to htdocs, select  setup_admin.php  and
     delete it.

     Why: the page already locks itself as soon as one administrator exists, so
     a stranger who finds the file cannot create an account. Deleting it is
     still the right habit - it removes the page completely. If you ever need it
     again (for instance after removing your only admin by mistake), upload the
     file again from this package, use it once, and delete it again.

     If you would rather keep the file, that is acceptable: it refuses to do
     anything while an administrator exists and it never reveals whether a
     particular e-mail is registered.

9. STEP 8 - SIGN IN AND SET UP YOUR SHOP
================================================================================

  Sign in at  https://your-subdomain/login.php  and you will be offered the
  admin dashboard, or go directly to  https://your-subdomain/admin/index.php .
  The admin link is not shown to customers in the shop menus.

  Do these five things first:

  1. STORE SETTINGS  ->  Admin  ->  Settings
     * Store name and tagline.
     * The announcement strip at the very top (free shipping promotion etc.).
     * Contact e-mail, phone and address shown in the footer and contact page.
     * Shipping fee (default PHP 99) and the free-shipping threshold (default
       PHP 1,500). Orders at or above the threshold ship free automatically.
     * How many products and orders per page.
     * Which payment methods are switched on: Cash on delivery, manual GCash
       transfer, and/or pick up in store.
     * Manual payment details: the GCash account name and number customers
       should send to, plus the safety reminder text shown next to it.
     Press Save.

  2. CATEGORIES  ->  Admin  ->  Categories
     Ten starter categories already exist. Edit, hide, reorder or add your own.
     Hiding a category hides it from the shop menus without deleting anything.

  3. PRODUCTS  ->  Admin  ->  Products  ->  Add a product
     Every field that matters is here: name, category, author/creator, ISBN,
     format, language, pages, price, compare-at price (creates the discount
     badge), stock, low-stock threshold, description and flags for
     Bestseller / New arrival / Staff pick / Featured on the home page.
     Upload a cover image (JPG, PNG, GIF or WebP up to 2 MB). The uploader
     checks the real file type, renames the file randomly and refuses anything
     that is not a readable image. Leave the image empty and the shop uses the
     clean placeholder cover.

  4. INVENTORY  ->  Admin  ->  Inventory
     A single table for stock: type a new quantity, or add a delivery on top of
     the current figure. The "Running low" view lists everything at or below
     your low-stock threshold.

  5. PAYMENTS  ->  Admin  ->  Payments (see section 10)
     This is where you approve or reject manual GCash payments.

  Other admin screens: Orders (search, filter, status updates, internal notes
  and the customer's address and contact details), Customers, Reviews (approve
  or hide), Messages (contact-form enquiries), Discount codes, Reports (sales
  by date with a CSV export) and Audit log (who changed what, and when).

10. STEP 9 - TEST A REAL CUSTOMER ORDER AND A GCASH PAYMENT
================================================================================

  Do this once yourself so you know the whole flow works on your hosting.

  1. Open the shop in a private/incognito window (so you are not signed in as
     the administrator) and register a customer account at register.php.
  2. Add two or three books to the cart, change a quantity, then open the cart
     and check the subtotal, shipping fee and total.
  3. Press Checkout, fill in the delivery details, choose GCash transfer, and
     place the order. You are taken to an order confirmation page with a
     reference number such as AKL-20261012-8HJ2K.
  4. The confirmation page shows the GCash account name and number from your
     settings, the exact amount, and a box for the 13-digit reference number on
     the GCash receipt. Enter any test reference and submit. You may also attach
     a photo of a receipt (optional).
  5. Now sign in as the administrator and open Admin -> Payments. The payment
     is listed as "Pending verification" with the reference number and receipt.
     * Press Verify when the money has arrived. The customer's order then shows
       "Payment verified".
     * Press Reject if the reference is wrong. A reason is required. The
       customer sees your reason on their order page and can submit a new
       reference. Both decisions are written to the audit log with your name
       and the time.
  6. Back as the customer, open My account -> Orders to see the status change.
     Nothing is decided automatically: the shop never claims a manual payment
     was verified until a person approves it.
  7. Optional: as the admin, open the order, change its status from Pending to
     Confirmed, then Processing, Shipped, Delivered. Only sensible transitions
     are allowed; the customer sees each change in their order history.

  NOTE: the shop does not send e-mail (free hosting does not allow reliable
  outgoing mail), so order updates are shown on the site itself, in the
  customer's order history. Tell your real customers to check that page.

11. FREE SSL (THE PADLOCK) AND YOUR SITE ADDRESS
================================================================================

  FREE INFINITYFREE SUBDOMAIN (.rf.gd, .great-site.net and friends)
    SSL is issued automatically for the subdomain, so you usually do not need
    to request anything - just give it a little time after creating the account
    and check that  https://your-subdomain  loads without a warning. Note that
    the automatic certificate covers the subdomain itself, not "www." in front
    of it or deeper sub-subdomains, and custom certificates are no longer
    installed for these free subdomains.

  YOUR OWN DOMAIN
    Client area  ->  Free SSL Certificates  ->  New SSL Certificate . Enter the
    domain without http:// or www, press Create Order, then set up the CNAME
    records it shows (InfinityFree can do this automatically when its
    nameservers are used). When the status becomes Ready, press Request
    Certificate and then install it on the hosting account. DNS checks can take
    a few hours, so do this in the evening and check the next day.

  FORCING HTTPS
    Once the padlock works, open config/config.php and set

        define('FORCE_HTTPS', true);

    Every visitor is then redirected to https://. If you would rather do it in
    .htaccess, add a RewriteRule 301 to https - but test carefully: a mistake in
    .htaccess shows up as "500 Internal Server Error" (see section 12).

  SITE ADDRESS - a reminder that it is automatic
    Leave  SITE_BASE_URL  empty unless something is wrong. It only needs a
    value if you later move to a custom domain and the old links are cached, or
    if a proxy hides the real address.

12. TROUBLESHOOTING
================================================================================

  "Aklatan Market is almost ready" / finish-the-installation page
      config/config.php still has empty DB_ values. Fill them in (section 6).

  "We could not connect to the store database" (or a 500 error on every page)
      1. Check DB_HOST. It must be the MySQL Host Name from the control panel,
         NOT "localhost".
      2. Check DB_NAME and DB_USER - they contain a prefix such as if0_38612345
         and they are case-sensitive.
      3. Check DB_PASS. The correct password is the HOSTING ACCOUNT password
         (the one used for FTP), not your client-area login password.
      4. Make sure you created the database in the SAME hosting account as the
         website (each free account has its own database server).
      The error page shows which of these to check, and it never reveals your
      password.

  500 Internal Server Error right after uploading
      Usually .htaccess. Open it in the File Manager and comment out anything
      that starts with php_value, php_flag, Options or Header by putting a #
      in front of the line, then reload. Free hosts differ in which Apache
      modules they allow. The 500.php page is there for genuine PHP crashes -
      turn on APP_DEBUG temporarily to see the reason, then turn it off.

  403 Forbidden
      * Opening config/, includes/, database/, storage/ or tools/ on purpose is
        refused by design - that is a security feature, not a fault.
      * On your own pages, 403 usually means folder or file permissions. Use
        755 for folders and 644 for files. For uploads/products and
        uploads/payments use 755 (they must be writable).

  404 Not Found on pages that should exist
      The files are in the wrong folder. index.php, products.php and the rest
      must sit DIRECTLY in htdocs. If you uploaded a ZIP and extracted it into
      htdocs/aklatan-market/, move everything up one level.

  Links point to the wrong place / images missing
      Upload the assets folder unchanged, including its sub-folders. If the
      links are still wrong after a move, set SITE_BASE_URL in config.php.

  "This page is not working" or a security check page from the host
      InfinityFree sometimes shows a short browser check before your page.
      That is normal free-hosting behaviour; wait a moment and reload.

  Cannot upload a cover image
      Only JPG, PNG, GIF and WebP up to 2 MB are accepted, and the file must be
      a real image (renaming photo.txt to photo.jpg will be refused). Check
      that uploads/products is writable (755).

  Login says "too many failed attempts"
      Wrong passwords are counted per e-mail address and per IP address for 15
      minutes (8 attempts). Wait a quarter of an hour, or type a correct
      password - a correct password always works, even while the limit is
      active. You can change the limits in config/config.php.

  phpMyAdmin refuses the import
      The file is only about 58 KB, so this is unusual - make sure you selected
      the database first, and that "Partial import" is not ticked. If your
      hosting shows an upload-size warning, use the Import tab's own file
      picker (it uploads directly to the server) rather than dragging files in.

  I forgot my admin password
      Create a new administrator: upload setup_admin.php again and open it - it
      will only create an account while no administrator exists, so instead use
      Admin -> Profile while signed in, or ask hosting support to clear the
      password_hash of your admin row and then re-run setup_admin.php.

  Sample data I no longer want
      Admin -> Customers, or run
          DELETE FROM users WHERE email LIKE '%@example.com';
      in phpMyAdmin (orders, payments, reviews, wishlists and addresses are
      removed with them). The sample orders also disappear, so the reports
      start from zero - which is what you want before your first real sale.

13. SECURITY CHECKLIST BEFORE YOU SHARE THE LINK
================================================================================

  [ ] config/config.php contains YOUR database details and nothing is left
      blank. Your password lives only in that file (it is blocked from being
      downloaded by the .htaccess rules, and config/ has its own guard page).
  [ ] setup_admin.php has been deleted (or at least used exactly once).
  [ ] You signed in as admin and changed nothing else - there is no default
      account to change, which is the safest possible start.
  [ ] You decided what to do about the sample customers
      (DELETE FROM users WHERE email LIKE '%@example.com';).
  [ ] APP_DEBUG is false. FORCE_HTTPS is true once the padlock works.
  [ ] Store settings contain a real contact e-mail/phone and your real GCash
      account name and number, and the payment reminder text is accurate.
  [ ] You placed one test order yourself and verified one manual payment.
  [ ] You tried opening  /admin/index.php  while signed out - you should be sent
      to the sign-in page, and a customer account must never reach it either.
  [ ] Your hosting password is not reused from another site.

  What the shop already does for you: every query that touches user input is a
  prepared statement; passwords are stored with PHP's password_hash() and never
  in plain text; every form carries a CSRF token; output is escaped with
  htmlspecialchars(); cart, wishlist, profile and orders are locked to their
  owner; prices, stock, shipping, discounts and order status are always
  recalculated on the server and never trusted from the browser; uploads are
  type-checked and renamed; and the shop never asks for - or stores - a GCash
  PIN, one-time password or card number.

14. WHAT THE FREE PLAN DOES AND DOES NOT ALLOW
================================================================================

  Advertised by InfinityFree for the free plan (check your own control panel,
  as offers change):
    * about 5 GB of disk space and unlimited bandwidth,
    * PHP 8.x (8.4 is advertised at the time of writing) and MySQL 8.0 /
      MariaDB 11.4,
    * a free subdomain with free SSL, no ads on your pages,
    * a limit of roughly 50,000 "hits" (requests for files) per day. Exceeding
      it takes the account offline for up to 24 hours, and the counter resets
      every 24 hours. A normal small shop stays far below this, but a busy
      launch day with heavy images can burn through it, so keep your cover
      images reasonably small.
    * file-size limits: HTML, PHP and JS files roughly 1 MB each, other files
      up to about 10 MB, .htaccess up to about 10 kB.
    * your site must receive a few visits every month or the account can be
      considered inactive.

  NOT available on the free plan (and this shop does not need any of them):
    * Cron jobs and long-running background processes - Aklatan Market has no
      scheduled tasks at all: stock, totals and reports are calculated when a
      page is opened.
    * Reliable outgoing e-mail. PHP mail() is heavily restricted, so the shop
      deliberately does not depend on e-mail: enquiries are stored in the
      database and read in Admin -> Messages, and order updates appear in the
      customer's order history. If you later want "order shipped" e-mails, use
      an external SMTP service or a plugin-free mail API and send from a
      short PHP script of your own.
    * A paid payment gateway. Payments are Cash on delivery, manual GCash
      reference (verified by you in Admin -> Payments), or pick up in store.

  Also worth knowing: the free plan is a shared host, so very heavy traffic or
  an unusual amount of CPU may attract attention. For a small bookstore this is
  fine. If you outgrow it, the same files run on any ordinary PHP + MySQL
  hosting - only config/config.php has to change.

15. TESTING THE SHOP ON YOUR OWN COMPUTER (OPTIONAL)
================================================================================

  You do not have to do this, but it is handy for making changes without
  touching the live shop.

    1. Install XAMPP (Windows/macOS) or use your Distribution's
       apache2+php+mariadb packages (Linux).
    2. Copy this whole package into the web root (XAMPP: htdocs/aklatan).
    3. Start Apache and MySQL, open http://localhost/phpmyadmin and import
       database/aklatan_market.sql into a database named aklatan_test.
    4. In config/config.php set DB_HOST to localhost, DB_USER to root,
       DB_PASS to '' (empty) and DB_NAME to aklatan_test.
    5. Open http://localhost/aklatan/ and run setup_admin.php as in section 8.

  The starter catalogue was generated locally and every cover image is an
  original SVG file that ships with the package - no image is loaded from
  another website, so the shop also works offline and on a private network.
